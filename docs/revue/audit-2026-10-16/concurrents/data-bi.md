# Concurrents data/BI/ETL : parité de GeoStudio (2026-10-16)

Périmètre : Superset, Metabase, Airbyte, dbt, Dagster/Airflow, DuckDB/MotherDuck.
Méthode : documentation en ligne d'octobre 2026 (WebSearch en mode extended, pages de recap/blog), croisée avec le CODE de `core/` et `shell/` (lecture seule). Le récit de `CLAUDE.md` n'est jamais une preuve. `Preuve` = `fichier:ligne` relu dans cette session. Une ligne marquée (inv.) s'appuie sur `docs/revue/inventaire-fonctionnalites.jsonl` sans relecture complète du code : confiance moyenne.

Limites de la recherche : les résultats sur Airbyte 2.0/licence, sur le statut des contracts/tests de dbt Fusion et sur les Dives de MotherDuck étaient minces ; ces points sont signalés « non confirmé ». Le rachat de Dagster par Prefect (juillet 2026) vient d'une seule source de revue : à ne pas citer sans recoupement.

## 2. Score de parité du domaine

13 capacités BI : 9,5 / 13 (73 %). 17 capacités ETL/orchestration : 9 / 17 (53 %).
**Total : 18,5 / 30 = 62 %.** Barème : oui/dépassé = 1, partiel = 0,5, non = 0, toutes capacités pondérées de la même façon (une capacité de niche compte autant qu'une capacité centrale : lecture indicative).

Le BI est proche des concurrents sur les parcours (requête visuelle, IA, MCP, embarquement par jeton). L'ETL est solide sur l'exécution (cron, retry, déclencheurs, secrets) mais faible sur trois axes que les concurrents tiennent comme socle : l'étendue des sources, la transformation versionnée sous Git, et l'orchestration par assets avec backfill.

## 3. Dix écarts majeurs

1. **Étendue des sources (#14, #15)** : une douzaine de lecteurs de bases/fichiers contre 400 à 700 connecteurs chez Airbyte ; aucun CDC depuis une base tierce. Fort risque si le produit se vend aussi comme ETL généraliste (la décision Q2 le positionne horizontal).
2. **Pas de cache de résultats (#7)** : toute agrégation retombe sur DuckDB, aucun TTL ni invalidation ; coût sur les tableaux de bord très consultés.
3. **Transformations non versionnées en Git, sans `ref()` ni modèles réutilisables (#17, #25)** : pas de flux « pull request, CI, promotion » que les équipes data attendent de dbt.
4. **Pas de backfill ni de partitions (#23)** : impossible de rejouer une plage historique d'un pipeline, point central de Dagster et d'Airflow 3.2.
5. **Pas d'orchestration par assets ni de fraîcheur (#24)** : un pipeline ne se déclenche pas parce qu'une collection amont a changé ; aucune politique de fraîcheur déclarative.
6. **Lineage limité à l'item (#19)** : ni colonne, ni OpenLineage, ni documentation générée ; la parité avec Fusion/Dagster est hors de portée sans moteur d'analyse SQL.
7. **Pas de code utilisateur dans les pipelines (#26)** : toute logique hors catalogue d'op impose une extension ; `PythonCaller` différé.
8. **SQL Lab sans requêtes sauvegardées/partagées côté serveur (#3)** : historique en `localStorage` (`sqlLabHistory.ts`), perdu au changement de navigateur et non collaboratif.
9. **Rapports et alertes à canaux limités (#5)** : PDF seul planifié, pas de Slack/Teams natif, pas d'envoi Excel/CSV planifié (Superset l'a depuis juillet 2026).
10. **Format de lac non transactionnel (#27)** : GeoParquet plat compacté, sans time travel natif ni transactions ; DuckLake 1.0 (avril 2026) offre déjà des types geometry et le filtrage par statistiques, l'écart se creuse.

Écarts secondaires : couche sémantique sans dimensions ni API exposée (#4), SDK d'embarquement React absent (#6), tests de qualité non rattachés aux runs (#18).

## 4. Cinq avantages réels de GeoStudio

1. **Moteur spatial de bout en bout (#28, #11)** : DuckDB + `spatial` chargé en serveur (`duckdb_conn.py:31`), ~150 op incluant géométrie/SRID/raster, tuiles MVT et symbologie ; aucun des six concurrents ne combine ETL, requête et carte.
2. **Sécurité unifiée au niveau colonne et emprise sur tous les accès (#10)** : le même masquage et les mêmes limites géographiques s'appliquent au SQL Lab (`features/routes.py:742-757`), aux exports et au MCP ; Superset/Metabase appliquent la RLS ligne, pas l'emprise ni le masquage de colonne côté lac.
3. **Une seule porte d'autorisation pour l'IA (#8, #9)** : le MCP et le copilote réutilisent `can()` et les privilèges de l'utilisateur, avec brouillon jamais exécuté automatiquement (`mcp/tools/query_generation.py`).
4. **Objets de plateforme déclaratifs reliés (#19, #25)** : cartes, apps, datasets, pipelines, alertes sont des configs versionnées avec retour arrière (`configs/routes.py:277`) et graphe d'impact transversal (`lineage/service.py:186`), là où un BI et un ETL séparés n'ont aucun lien d'impact entre outils.
5. **Pile unique auto-hébergeable (#20-#22, #29)** : cron, déclencheurs fichier/webhook, retry avec reprise de checkpoint, secrets chiffrés et egress gardé dans un seul cœur Python/Postgres (procrastinate, sans broker), alors que la combinaison concurrente exige Airbyte + dbt + Dagster + Metabase.
