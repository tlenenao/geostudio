# d04 — Impression, atlas, rapports PDF

Audit en lecture seule du 2026-10-16, sans exécution de tests. Preuves relues dans le code (fichier:ligne). Le moteur est propre côté orchestration : annulation, reprise des jobs coincés, notifications best-effort, session isolée. Les défauts réels sont côté rendu.

Bilan : 10 constats vérifiés (1 Critical, 9 Important) + 2 Minor non vérifiés.

## Critical

### D04-01 — Un export d'app/dashboard (donc tout ReportSchedule) est capturé sans attendre les widgets [bug] — vérifié
- **Preuve** : `shell/src/pages/AppRuntimePage.tsx:79-83` appelle `markExportReady()` (dans un `requestAnimationFrame`) dès que `query.isSuccess` (la config) et `extensionsRegistered` sont vrais. Seuls `MapEditorPage.tsx:194` (idle MapLibre) et `AtlasPages.tsx:37` émettent un vrai signal. Aucun widget d'app (graphique, tableau, KPI, widget carte) ne signale son chargement ; le commentaire de `shell/src/shell/exportReady.ts` l'admet (« no per-widget fully rendered signal yet »). Or un ReportSchedule rend toujours une app via `bookmark.appId` + `pageId` (`core/app/reports/jobs.py:208-231`), et `core/app/export/jobs.py:189-191` attend ce signal.
- **Reproduction** : app avec graphique et tableau sur une collection de 100k lignes, un bookmark, un ReportSchedule cron. Le worker capture dès que `/configs` répond : spinners ou widgets vides dans le PDF. Idem via `POST /v1/export format=pdf` sur toute app.
- **Correctif** : compteur global d'opérations en cours (`useIsFetching` de React Query + callbacks `onReady` des widgets carte) exposé par un hook `useExportReadiness` ; `markExportReady` seulement quand `isFetching===0`, que les MapView de widgets ont émis `idle`, après debounce de 300 ms. Timeout dégradé qui marque le PDF « incomplet » au lieu de capturer du vide en silence.

## Important

### D04-02 — Atlas silencieusement tronqué à 100 fiches, non trié, sans filtre de contexte [bug] — vérifié
- **Preuve** : `shell/src/builder/print/AtlasPages.tsx:27-34` : `client.queryDataSource(source)` puis `.slice(0, atlas.maxPages)`. `queryDataSource` ne retourne qu'une page (`shell/src/api/domains/datasets.ts:103-107,188,298-299`), aucun `limit` envoyé, et la route OGC applique `limit=100` par défaut (`core/app/features/routes.py:320`). `AtlasConfig.maxPages` autorise jusqu'à 200 (`core/app/configs/schemas.py:632`). Aucun `sortby` : ordre PostGIS. `queryKey ["atlas", dataSourceId]` ignore `ctx` (bookmark/cross-filter) alors que ReportSchedule le transmet.
- **Reproduction** : collection de 150 entités, `maxPages=200` : 100 pages, sans message ; ordre non reproductible entre exports.
- **Correctif** : `limit=maxPages` et `sortby` (`AtlasConfig.sortBy`), pagination via `queryDataSourcePage` jusqu'à `maxPages`, bandeau « atlas tronqué à N/M » si total > `maxPages`, `ctx` dans la clé de requête.

### D04-03 — Le jeton d'export est un bearer utilisateur complet, non borné à l'item, à la lecture ni au statut du job [securite] — vérifié
- **Preuve** : `core/app/auth/export_tokens.py:18,39-49` : `decode_export_token` ne lit que `tenant_id`/`user_id`/`job_id`. `core/app/auth/dependency.py:230-240` renvoie le `User` complet (tous privilèges) pour n'importe quelle route (écriture, suppression, MCP, secrets). Pas de lien à `item_id`, pas de scope lecture seule, `job_id` jamais revérifié (annulation/fin de job n'invalident rien). Le jeton circule en URL (`?exportToken=`, `core/app/export/jobs.py:263` ; `shell/src/auth/exportAwareToken.ts:20-21`) : logs Traefik/shell, historique Chromium, lisible par tout JS de la page (widgets d'extension tiers inclus, ADR 0013).
- **Reproduction** : pendant les 120 s de validité, `curl -H 'Authorization: Bearer <jeton>' -X DELETE /v1/items/<item de l'utilisateur>`.
- **Correctif** : claims `scope='export:read'` et `item_id` ; dans `get_current_user`, refuser toute méthode hors GET/HEAD et tout chemin hors allowlist (configs de l'item, collections/tuiles liées, datasets) pour un jeton d'export ; vérifier que le job est encore `running` (requête indexée) ; transmettre le jeton par en-tête (`context.set_extra_http_headers`) ou cookie plutôt que par l'URL.

### D04-04 — Aucune garde d'egress sur le Chromium du worker d'export (SSRF aveugle), jumelle oubliée [securite] — vérifié
- **Preuve** : `core/app/export/jobs.py:159-199` (`_launch_and_navigate`) lance `chromium.launch(headless=True)` sans `page.route`/`context.route` ni filtrage d'hôtes (aucune occurrence de `route(` dans `core/app/export`). Le commentaire de `PrintLayout` (`core/app/configs/schemas.py:641-643`) affirme « pas de requête sortante » pour le logo, mais le widget « image » rend `<img src={props.src}>` avec URL libre (`shell/src/builder/widgets/index.tsx:136-139`), et les couches feature/WMS/tuiles acceptent des URL libres. Le conteneur est sur `gis-net` (minio, pgbouncer, core ; metadata 169.254.169.254 sur la cible OCI : `docker-compose.yml:746-783`, `deploy/export-worker/Dockerfile`). Le dépôt garde l'egress ailleurs (net_pin, harvest, LLM, SMTP) : piège n°14.
- **Reproduction** : widget image `src=http://169.254.169.254/opc/v2/instance/` ou `http://minio:9000/...` puis `POST /v1/export format=png` ; le worker émet la requête depuis le réseau interne (aveugle).
- **Correctif** : `context.route('**/*')` avec allowlist (origine shell, origine cœur, hôtes de tuiles du tenant) ; sinon refus des IP privées/loopback/link-local via `app.net_pin` (DNS pinné). Désactiver service workers et popups. Test de non-régression avec faux `page.route`.

### D04-05 — Le jeton d'export expire (120 s) en même temps que le budget de rendu [bug] — vérifié
- **Preuve** : `mint_export_token(ttl_seconds=120)` (`core/app/auth/export_tokens.py:39`) est émis avant la vérification d'annulation et le lancement de Chromium (`core/app/export/jobs.py:258-278`) ; `RENDER_TIMEOUT_MS` = 120 000 (`core/app/export/rendering.py:14`). Toute requête après T0+120 s reçoit 401 ; le shell n'a pas de session de repli (`App.tsx:48-51` coupe le refresh en mode `exportToken`) et `markExportReady` peut déjà être levé : données manquantes, job « done ».
- **Reproduction** : atlas de 200 pages ou carte à tuiles 3D lentes > 2 min : dernières requêtes en 401, job `done`.
- **Correctif** : TTL = `RENDER_TIMEOUT_MS` + marge (~300 s), émis juste avant `page.goto`, combiné à la liaison au job (révocation à la fin, cf. D04-03). Écouter `page.on('response')` et faire échouer le job sur 401.

### D04-06 — Résolution fixée à 96 dpi, aucun réglage de DPI ni d'échelle [parite] — vérifié
- **Preuve** : `core/app/export/jobs.py:183-186` : `browser.new_page(viewport=...)` sans `device_scale_factor` ; carte WebGL rastérisée à 794x1123 px pour une A4 (`core/app/export/rendering.py:17-28,47-48`), y compris dans le PDF. `PrintLayout` (`core/app/configs/schemas.py:635-649`) n'expose ni dpi, ni échelle fixe, ni emprise d'impression ; barre d'échelle = contrôle MapLibre interactif (`PrintOverlays.tsx:3-4`) donc infidèle à l'échelle papier ; formats limités à a4/a3 (`schemas.py:636`). ArcGIS Pro Layouts : 300-600 dpi à l'échelle choisie.
- **Reproduction** : PDF A3 d'une carte, zoom 200 % : fond et étiquettes pixellisés ; aucun champ de config pour corriger.
- **Correctif** : `PrintLayout.dpi` (96|150|300|600, défaut 150), `scale` (dénominateur), `pageSize` étendu (a0..a5, letter, legal, custom mm), `margins`. Worker : `device_scale_factor=dpi/96` avec plafond de pixels (mémoire), `prefer_css_page_size`.

### D04-07 — Atlas = fiches tabulaires, pas de « map series » [differenciateur] — vérifié
- **Preuve** : chaque page d'atlas ne rend que `EntityFiche` (`shell/src/builder/print/AtlasPages.tsx:47-58`, `EntityFiche.tsx:37-48` : un `<h2>` et un `<dl>`), aucune `MapView`. `core/app/export/routes.py:83-92` refuse l'atlas pour `kind='map'` (422, l.89) et pour tout format autre que pdf. Pagination CSS `break-after-page` sans numéro, table des matières ni index. C'est le cœur d'ArcGIS Pro Map Series / QGIS Atlas.
- **Reproduction** : `POST /v1/export {itemId:<carte>, format:'pdf', atlas:true}` → 422 ; atlas d'app : PDF sans aucune carte.
- **Correctif** : mini-carte par entité (MapView en export, emprise = bbox + marge, entité surlignée, `onReady` agrégé) avant la fiche ; autoriser `kind='map'` (couche de couverture = `atlas.dataSourceId`) ; index et numéros de page.

### D04-08 — Mise en page non composable [differenciateur] — vérifié
- **Preuve** : `PrintLayout` = 8 champs fixes (titre, légende, cartouche, logo, flèche, échelle, texte, atlas) en positions absolues codées en dur (`shell/src/builder/print/PrintOverlays.tsx:78-150`, notamment l.94-146 ; `core/app/configs/schemas.py:635-649`). Pas de cadres déplaçables, multi-cartes, graphique/tableau, modèles de page. Pied de page PDF unique « Généré le » (`core/app/export/rendering.py:44-47`, `60-82`) ; pas de saut de page contrôlable pour apps/dashboards.
- **Reproduction** : impossible de produire une planche carte principale + encart + graphique + tableau récapitulatif.
- **Correctif** : `printLayout` = document déclaratif d'éléments (map|chart|table|legend|text|image|scalebar, x/y/w/h en mm, références de widget) rendu par un `PrintSheet` unique partagé carte/app (règle d'architecture 2 : générable par MCP/IA), gabarits partageables.

### D04-09 — ReportSchedule : un seul format, une seule app, pas de pièce jointe, pas de rejeu [parite] — vérifié
- **Preuve** : `ReportSchedulePayload` n'a que `bookmarkItemId`, `refreshPolicy`, `channels` (`core/app/configs/schemas.py:590-603`). Job créé avec `format='pdf'` en dur, sans scope (`core/app/reports/jobs.py:222-231`) : pas de PNG, atlas, CSV/XLSX (alors que SP-16a existe), ni multi-bookmarks. E-mail = lien présigné seulement (l.383, TTL 7 j), jamais le PDF (l.381-384, 404-412). Rendu en erreur : pas de retry avant le prochain cron ; `shell/src/builder/report/ReportRunPanel.tsx:33-38` confirme « jamais déclenché que par le cron » : pas d'« Exécuter maintenant » ni de test d'envoi.
- **Reproduction** : rapport hebdomadaire dont le rendu échoue sur incident transitoire : destinataire sans PDF pendant 7 jours.
- **Correctif** : payload étendu (`format`, `atlas`, `bookmarkItemIds`, `retry {max, delayMinutes}`, `attachment`) ; `POST /v1/reports/{id}/run` (envoi d'essai) ; ré-armement d'un run en erreur au tick suivant.

## Minor — non vérifiés (à confirmer avant correction)

### D04-10 — Un bookmark de carte est ignoré à l'export : `ctx` n'est lu que par AppRuntimePage [bug] — non vérifié
- **Preuve (rapportée)** : le worker ajoute `&ctx=` quelle que soit la route (`core/app/export/jobs.py:259-265`) ; `MapEditorPage.tsx:187-212` n'a aucune référence à `ctx`/`decodeAnalyticsContext` (0 occurrence) ; seul `AppRuntimePage` le décode (l.100-110). Un rapport dont `bookmark.appId` désigne une carte ignore donc extent et plage temporelle (`core/app/reports/jobs.py:222`).
- **Reproduction** : bookmark carte avec extent + timeRange, ReportSchedule dessus : PDF en vue par défaut.
- **Correctif** : décoder `ctx` dans le mode `isExportRender` de `MapEditorPage` (fitBounds, timeRange) avant d'attendre `idle` ; ou refuser à la création un bookmark dont l'item n'est pas une app (`configs/service.py`).

### D04-11 — Pied de page PDF probablement invisible, SVG d'export = enveloppe raster, pas de numérotation [polish] — non vérifié
- **Preuve (rapportée)** : `page.pdf(display_header_footer=True, footer_template=...)` sans `margin` ni `prefer_css_page_size` (`core/app/export/rendering.py:75-82`, gabarit l.44-47) : le pied de page, dessiné dans la marge (0 par défaut), serait rogné (à confirmer visuellement). Le format `svg` est un PNG base64 dans un `<svg>` (l.50-58). Classes `pageNumber`/`totalPages` non utilisées alors que l'atlas atteint 200 pages.
- **Reproduction** : PDF d'atlas de 10 pages : pas de « Page n/N », pied absent ou tronqué.
- **Correctif** : `margin={'top':'10mm','bottom':'15mm',...}` + `footer_template` avec `<span class='pageNumber'>/<span class='totalPages'>` ; renommer « svg (image) » ou le retirer jusqu'à un vrai rendu vectoriel.

## Avantages et différenciateurs

- Orchestration saine : annulation de job, reprise des jobs coincés, notifications best-effort isolées du commit de statut, session de rendu isolée.
- Impression et rapports pilotés par configuration déclarative (`printLayout`, `ReportSchedule`, `Bookmark`) : générables par MCP/IA, ce qu'ArcGIS Layouts ne propose pas ; D04-08 propose d'en faire un document d'éléments composables pour creuser cet écart.
- Un bookmark (extent, temps, cross-filter) peut être rendu en PDF planifié avec livraison par canaux (webhook/e-mail) : base d'un équivalent d'ArcGIS Reports / Power BI subscriptions, à compléter par D04-09.
- Atlas par entité sur un même runtime que les apps (règle d'architecture 3) : l'ajout de cartes recadrées (D04-07) donnerait une map series sans second moteur.

Aucun constat écarté. Les 2 constats Minor (D04-10, D04-11) restent marqués non vérifiés.
