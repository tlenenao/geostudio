# d09 — Portails, sites, storytelling, catalogue public

Audit en lecture seule du code, sans suite de tests lancée. Aucune faille de sécurité confirmée dans ce périmètre : les routes publiques filtrent bien tenant, publication et type.

Synthèse : 1 bug de parcours majeur (types « map »/« dataset » du catalogue public qui mènent à « introuvable »), 1 bug d'avertissement à la publication, le reste est du retard de parité avec ArcGIS Hub et StoryMaps (recherche, facettes, fiche dataset, SEO, liens profonds, multi-tenant).

## Important

### 1. Items publiés « map » et « dataset » listés au catalogue public mais « introuvable » à l'ouverture
- Tag : bug
- Preuve : `core/app/items/repository.py:627` (`PUBLIC_KINDS = ("site","app","dashboard","map","dataset")`) ; `shell/src/pages/PublicCatalogPage.tsx:20`, `:57-62` (filtre de type et navigation vers `/public/items/:pk`) ; `shell/src/pages/PublicItemPage.tsx:34-48` ; `shell/src/api/domains/apps.ts:70-93` (`getPublicAppConfig` lève « config has no layout » si `c.layout` est absent) ; `core/app/configs/schemas.py:179-185`, `:699-700` (seuls app/dashboard/site exigent `layout`) ; `core/app/ingestion/importer.py:421-443` (l'import crée des items map/dataset sans layout). La page affiche `PublicNotFound` avec noindex, alors que `/public/items/{id}/social-preview` et le sitemap annoncent l'URL. `DatasetPage` (`/public/datasets/:collectionId`) existe mais n'est liée depuis aucun item « dataset ».
- Reproduction : publier une carte importée en GeoJSON, ou un dataset tabulaire importé ; ouvrir `/public` sans connexion, cliquer la carte : « introuvable ».
- Correctif : dans `PublicItemPage`, router selon `item.resourceType` (dataset vers `/public/datasets/{collectionId}`, map vers une vue carte lecture seule en synthétisant un AppConfig plein écran comme le `previewConfig` de `DatasetPage`). À défaut, retirer map/dataset de `PUBLIC_KINDS` et du sitemap. Ajouter un E2E qui ouvre un item publié de chaque type.

### 2. Aucune vérification à la publication que les données référencées sont lisibles publiquement
- Tag : bug
- Preuve : `core/app/items/service.py:112-126` (`update_item_service` ne vérifie que `require_publish_rights`, n'inspecte jamais les `dataSources`) ; `core/app/public/routes.py:266-276` (config servie telle quelle) ; `shell/src/pages/SitePublicPage.tsx:55-61`. Les widgets lisent via les routes de features qui exigent `can()` ou collection `is_public`.
- Reproduction : créer une app sur une collection non publique, la publier, ouvrir `/public/items/{pk}` en navigation privée : widgets sans données, sans avertissement à l'auteur.
- Correctif : au passage `isPublished=true` (service et MCP), résoudre les collections référencées et renvoyer un avertissement structuré (ou 422 avec option de forcer) listant celles non `is_public` ; proposer « publier aussi ces collections » dans l'UI.

### 3. Fiche dataset publique pauvre
- Tag : parite
- Preuve : `shell/src/pages/DatasetPage.tsx:77-134` n'affiche que titre, description, nombre d'entités, téléchargements, profil, carte+table. `core/app/collections/schemas.py:147-157` porte license, licenseUri, producer, contact, updateFrequency, lineage, language, version, temporalStart/End (SP-41), non rendus. `core/app/public/routes.py:228-239` : le social-preview ne transmet que title et description.
- Reproduction : renseigner licence et producteur sur une collection publique, ouvrir `/public/datasets/{id}` anonymement : rien.
- Correctif : bloc « Métadonnées » (licence avec lien, producteur, contact, fréquence, période, lignage), dictionnaire de données (schéma), liens vers `/v1/collections/{id}/items`, `/stac/collections/{id}`, `/dcat/datasets/{id}`.

### 4. Catalogue public sans recherche plein texte, facettes, tri ni filtre spatial
- Tag : parite
- Preuve : `core/app/public/routes.py:94-109` (seuls type, tag, page, pageSize) ; `shell/src/pages/PublicCatalogPage.tsx:30-80` (tag en texte libre) ; `core/app/items/repository.py:653-712` et `:571-624` (`list_items`/`get_facets` authentifiés ont q, sort, owner, bbox, status). Les collections `is_public` ne sont pas listées dans `/public` (sitemap et widget datasetCard seulement).
- Reproduction : avec 200 items publiés, aucune recherche par titre ni filtre par emprise ; une collection publique sans item n'est atteignable que par URL.
- Correctif : ajouter q, sort, bbox et `GET /public/facets` ; lister les collections `is_public` comme « Jeux de données » ; réutiliser `_visible_items_base_query` avec un scope anonyme.

### 5. Googlebot/bingbot détournés vers un stub HTML maigre, sans JSON-LD
- Tag : differenciateur
- Preuve : `docker-compose.yml:501-525` et `docker-compose.prod.yml:227-247` (routeurs `seo-bots*` incluent Googlebot et bingbot, réécriture vers `/social-preview`) ; `core/app/public/routes.py:53-82` (`<h1>`+`<p>` seulement) ; commentaires faux dans `shell/src/shell/useDocumentMeta.ts:3-14` et `shell/src/pages/SitePublicPage.tsx:28-34` (affirment que Googlebot exécute le JS). Vérifié : aucune occurrence de `ld+json` côté pages publiques (seul le DCAT en a, `core/app/dcat/routes.py:31`). Pas de noindex pour un item déprécié.
- Reproduction : `curl -A Googlebot https://<hôte>/sites/<slug>` renvoie le stub d'une dizaine de balises.
- Correctif : retirer Googlebot/bingbot de la regex (ils rendent le JS) ou servir un vrai rendu serveur ; enrichir le stub d'un JSON-LD schema.org/Dataset (name, description, license, keywords, spatialCoverage, temporalCoverage, distribution) pour Google Dataset Search ; corriger les commentaires.

### 6. Aucun lien profond par page/chapitre (sites publics et story)
- Tag : differenciateur
- Preuve : `shell/src/shell/routes.tsx:379-382` (seules `/sites/:slug` et `/public/items/:pk`) ; `shell/src/pages/SitePublicPage.tsx:55-61` et `PublicItemPage.tsx:51-56` rendent `AppRenderer` sans `pageId`/`onNavigate` ; page active en `useState` (`shell/src/builder/AppRenderer.tsx:132-152`) ; `AppRuntimePage.tsx:33` accepte `pageId` (asymétrie avec l'app authentifiée). Le titre de chapitre (`Page.name`) n'est jamais rendu : le bandeau n'affiche que « Chapitre n / N ».
- Reproduction : publier un site à 3 pages ou une story, passer au chapitre 2, recharger : retour au chapitre 1 ; le bouton Précédent du navigateur quitte le site.
- Correctif : routes `/sites/:slug/:pageId?` et `/public/items/:pk/:pageId?`, passer `pageId`/`onNavigate` à `AppRenderer`, afficher `Page.name`, lister les chapitres dans le sitemap et le stub SEO.

### 7. Portail mono-tenant en dur
- Tag : differenciateur
- Preuve : `core/app/public/routes.py:116`, `:126`, `:136-141` (`DEFAULT_TENANT_SLUG` partout, vérifié aux lignes 116, 140, 216, 233, 270) ; `core/app/items/repository.py:653-656`, `:832-834`. Aucune résolution de tenant par hôte ou en-tête.
- Reproduction : publier un site dans un tenant autre que `default` : 404 sur `/v1/public/sites/{slug}`.
- Correctif : table host→tenant résolue dans une dépendance commune aux routes `/public` ; champ « domaine personnalisé » sur l'item site, puis middleware Traefik dynamique.

### 9. Facettes et sitemap en mémoire Python (non vérifié)
- Tag : dette
- Preuve : `core/app/items/repository.py:571-624` (`get_facets` agrège en Python) ; `core/app/public/routes.py:132-144`, `:28` (jusqu'à 50 000 `ItemRead` complets par requête anonyme, cache `max-age=300` côté en-tête seulement). Pas d'index GIN sur les mots-clés.
- Reproduction : 50 000 items publiés, `GET /v1/public/sitemap.xml` en boucle.
- Correctif : facettes en SQL (`jsonb_array_elements_text` + `GROUP BY`), index GIN, projection minimale et cache TTL 5 min pour le sitemap.

## Avantages et différenciateurs

- Routes publiques correctement filtrées par tenant, état de publication et type (`PUBLIC_KINDS` exclut alert/pipeline/report).
- Mode story déjà fondé sur `onEnter` + ActionBus (flyTo à l'entrée de chapitre), base réutilisable pour du scrollytelling.
- Profil de données et téléchargements sur la fiche dataset, STAC et DCAT-AP natifs dans le cœur : avec un JSON-LD schema.org/Dataset (constat 5), le SEO données dépasserait ArcGIS Hub.
- Prévisualisation sociale et sitemap serveur déjà présents.
