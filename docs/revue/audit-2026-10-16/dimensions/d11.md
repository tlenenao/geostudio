# Audit d11 — ETL : lecteurs/écrivains et op expérimentales

Date : 2026-10-16. Lecture seule. Périmètre : lecteurs/écrivains de pipeline et les 32 op `experimental`.

## Méthode et limites

- Cinq défauts ont été reproduits par exécution locale (Python, DuckDB, doubles de test), sans postgis-test ni conteneur : #1, #2, #3, #4, et #5 (constaté par lecture avec un faux client).
- Les autres constats reposent sur la lecture du code.
- Aucun rejeu sur service réel : aucun conteneur (pas d'image Mongo, RabbitMQ, FTPS en local) et aucun accès réseau tenté. Mongo, AMQP et FTPS exigent un TLS vérifié contre les CA publiques (voir #9).
- Les constats les plus lourds sont des défauts de conception visibles dans le code, pas des fuites exploitables sur la porte.

## Périmètre solide

La porte `CORE_PIPELINE_EXPERIMENTAL_OPS_ENABLED` est appliquée sur tous les chemins d'écriture (`configs/service.py`, `configs/routes.py`, MCP, `_validate_node`), à l'exécution (`runtime._prepare`) et dans le catalogue. Chaque appel HTTP des 32 op passe par une session gardée contre le SSRF avec épinglage DNS, et les secrets sont liés à un `baseUrl`.

3 Important (#1, #2, #5), 1 Important produit (#6, différenciateur), le reste en Minor.

## Important

### #1 — Lecteurs SQL externes : aucune connexion read-only, garde SELECT-only purement syntaxique
- Sévérité : Important — Tag : securite — Vérifié
- Fichiers : `core/app/pipelines/connector_runtime.py:300-359`, `core/app/analytics/sql_sandbox.py:60-66`, `core/app/pipelines/connector_runtime.py:619-649`
- Preuve : `_stream_sql` ouvre `sa.create_engine(dsn, connect_args=...)` avec seulement des timeouts. `_timeout_connect_args` ne pose ni `default_transaction_read_only`, ni `SET TRANSACTION READ ONLY`, ni équivalent. `validate_select_only` ne vérifie que le type du nœud racine ; le commentaire de `materialize_postgres_connector` le qualifie lui-même d'heuristique. Mesure : `validate_select_only(parse_ast(duckdb.connect(), q))` accepte `SELECT nextval('s')` et `SELECT pg_terminate_backend(123)`. La requête part telle quelle vers la base distante avec les droits du DSN du coffre. Le secret appartient à un utilisateur du tenant, qui peut le partager à un auteur de pipeline.
- Reproduction : `cd core && PYTHONPATH=. .venv/bin/python -c "import duckdb;from app.analytics.sql_sandbox import *;c=duckdb.connect();validate_select_only(parse_ast(c,\"SELECT pg_terminate_backend(123)\"));print('accepté')"`. Effet réel : un `reader.connector.postgres` avec cette requête sur une base de test et un DSN en écriture ; l'appel de fonction s'exécute.
- Correctif : imposer le read-only côté pilote (`options=-c default_transaction_read_only=on` pour Postgres, `SET TRANSACTION READ ONLY` ou `ApplicationIntent=ReadOnly` selon le moteur, `execution_options(postgresql_readonly=True)`). Pour les moteurs sans mécanisme fiable, documenter dans l'UI la nécessité d'un DSN en lecture seule et refuser les fonctions hors allowlist.

### #2 — reader.arcgisonline : troncature silencieuse au plafond `maxFeatures`
- Sévérité : Important — Tag : bug — Vérifié
- Fichiers : `core/app/pipelines/ops/cloudfiles.py:593`, `core/app/pipelines/ops/cloudfiles.py:632-670`
- Preuve : la boucle s'arrête quand `len(features) >= want` (`want` = min(`maxFeatures`=10 000 par défaut, plafond plateforme)) et le code fait `_features_frame(features[:want])` sans erreur ni colonne/métadonnée de troncature. Les lecteurs sœurs (Mongo, SQL, Kinesis) lèvent « plafond dépassé ». Mesure : `_http_get` remplacé par un double renvoyant toujours `exceededTransferLimit: true`, `maxFeatures=2500` : 3 pages (0,1000)(1000,1000)(2000,500), 2500 lignes, aucune alerte. Une couche de 50 000 entités donne 10 000 lignes sans signal. La pagination `resultOffset` n'envoie pas `orderByFields` (doublons ou pertes possibles entre pages) et ignore `maxRecordCount`.
- Reproduction : script ci-dessus (monkeypatch de `cloudfiles._http_get`). Réel : couche FeatureServer de plus de 10 000 entités, `maxFeatures` par défaut : le run réussit avec 10 000 lignes.
- Correctif : si la dernière page porte encore `exceededTransferLimit` alors que `len(features) >= want`, lever `PipelineRuntimeError` (ou statut `succeeded_with_warnings`). Ajouter `orderByFields=<OBJECTID>`, lire `maxRecordCount` via `?f=json`, paginer par `objectIds`. Réutiliser `reader_state` pour une lecture incrémentale.

### #5 — reader.mongodb : filtre JSON non converti en types BSON
- Sévérité : Important — Tag : parite — Vérifié (par lecture, faux client)
- Fichiers : `core/app/pipelines/ops/dbio2.py:60-110`, `core/app/pipelines/ops/dbio2.py:274-282`
- Preuve : `ReaderMongoDbParams.filter` est un `dict` JSON validé par `_check_filter` (interdit `$where`/`$function`/`$accumulator`) puis passé tel quel à `find(p.filter, ...)`. Aucune occurrence de `bson.json_util`, `$oid` ou `$date` dans le module. `{"_id": {"$oid": "..."}}` ou `{"createdAt": {"$gte": {"$date": "..."}}}` compare à un sous-document littéral et ne retourne rien (échec silencieux). Les deux filtres les plus courants (identifiant, date) sont inutilisables. `$expr`, `$regex`, `$text` non bornés ne sont pas limités, seul `maxTimeMS` protège.
- Reproduction : faux client capturant l'argument de `find` ; `read_mongodb(... params={"filter": {"_id": {"$oid": "6500..."}}})` ; le dict reçu contient `{'$oid': '...'}` brut.
- Correctif : `bson.json_util.loads(json.dumps(p.filter))` (mode relaxed) avant `find`, en conservant `_check_filter` en amont et en aval. Test de non-régression sur `$oid` et `$date`.

### #6 — Lecteurs SQL externes : aucune détection de colonnes géométrie
- Sévérité : Important — Tag : differenciateur — Vérifié
- Fichiers : `core/app/pipelines/connector_runtime.py:518-548`, `core/app/pipelines/runtime.py:411-580`
- Preuve : `_run_dlt_and_attach` copie les colonnes telles que dlt les a normalisées vers une table TEMP. Aucun traitement de géométrie dans `connector_runtime.py` (aucune occurrence de geometry, wkt, ST_, SDO_GEOMETRY) : Snowflake, BigQuery, MSSQL, Oracle et Postgres/PostGIS livrent les colonnes spatiales en texte ou binaire opaque, tandis que `_read_connector_*` annonce un SRID 4326 sans géométrie présente. Les « query layers » ArcGIS et les lecteurs spatiaux FME transforment ces colonnes et gèrent le SRID. Ici l'utilisateur écrit à la main `ST_AsText` côté distant puis `transform.createGeometry` en aval, avec un SRID supposé. Manque net pour une plateforme géospatiale.
- Reproduction : lecture du code ; `SELECT id, geom FROM t` sur un PostGIS distant ne produit pas de colonne `geometry` typée.
- Correctif : paramètres `geometryColumn` / `geometryFormat` (wkb, wkt, ewkb, geojson) et `srid` sur les 6 lecteurs SQL, conversion par `ST_GeomFromWKB`/`ST_GeomFromText` à la matérialisation, SRID réel au lieu du 4326 fixe.

### #4 — reader.azurequeue : garde anti-DTD contournable
- Minor — securite — non vérifié (mesuré localement)
- Fichier : `core/app/pipelines/ops/messaging.py:697-702`
- Preuve : `low = body[:4096].lower()` ne cherche `<!doctype`/`<!entity` que dans les 4096 premiers octets, puis `ElementTree.fromstring(body)` parse tout. Un prologue XML, un commentaire de 5000 octets, puis `<!DOCTYPE a [<!ENTITY e "BOOM">]>` : `_parse_queue_xml` renvoie `message_id: 'BOOM'`, l'entité est expansée. Impact borné par le `baseUrl` du secret et l'absence de résolution d'entités externes (expat limite l'amplification).
- Reproduction : `from app.pipelines.ops.messaging import _parse_queue_xml; _parse_queue_xml(b'<?xml version="1.0"?><!--'+b'x'*5000+b'--><!DOCTYPE a [<!ENTITY e "BOOM">]><QueueMessagesList><QueueMessage><MessageId>&e;</MessageId></QueueMessage></QueueMessagesList>')`
- Correctif : tester `b'<!doctype' in body.lower()` sur tout le corps, ou `defusedxml.ElementTree.fromstring`.

### #7 — WMS 1.3.0 : inversion des axes uniquement pour EPSG:4326
- Minor — bug — non vérifié
- Fichier : `core/app/pipelines/ops/readers2.py:1052-1066`
- Preuve : `bbox_q = (miny, minx, maxy, maxx) if p.version == "1.3.0" and p.srid == 4326 else p.bbox`. En WMS 1.3.0 l'ordre suit la définition EPSG : lat/lon aussi pour 4258 (ETRS89, INSPIRE), 4269, 4230, 4617. Pour ces CRS le bbox part en lon/lat : image vide ou mal placée, puis `_image_frame` plaque l'emprise demandée : coordonnées fausses sans erreur.
- Reproduction : par lecture ; `srid=4258, version=1.3.0` donne `bbox_q == p.bbox`.
- Correctif : dériver l'ordre via pyproj (`CRS.from_epsg(srid).axis_info[0].direction == 'north'`). Tests sur 4258 et 3857.

### #9 — MongoDB, AMQP, FTPS : CA système uniquement
- Minor — parite — non vérifié
- Fichiers : `core/app/pipelines/ops/cloudfiles.py:816`, `core/app/pipelines/ops/messaging.py:1056`, `core/app/pipelines/ops/dbio2.py:109-125`
- Preuve : `ssl.create_default_context()` pour FTPS et AMQP, `tls=True` sans `tlsCAFile` pour Mongo ; TLS non désactivable. Les serveurs on-prem à PKI interne sont inutilisables ; combiné à la garde d'egress (plages privées refusées hors `CORE_PIPELINES_EGRESS_ALLOWLIST`), ces op ne servent que des services publics. Explique aussi l'absence de rejeu sur conteneur local sans CA injectée.
- Reproduction : par lecture ; un `rabbitmq`/`mongod` local à certificat auto-signé donne `AMQP connection failed: SSLCertVerificationError`.
- Correctif : champ `caBundle` (PEM chiffré) dans le kind de secret, transmis à `ssl.create_default_context(cadata=...)` et `tlsCAFile` (fichier temporaire), vérification du nom d'hôte conservée ; rejeu CI sur conteneurs jetables avec CA de test.

### #10 — transform.mcpCall : séquentiel, jointure sans ORDER BY, session jamais fermée
- Minor — dette — non vérifié
- Fichiers : `core/app/pipelines/ops/messaging.py:1237-1245`, `:1334-1349`
- Preuve : `row_number() OVER ()` dans deux requêtes distinctes sans `ORDER BY` : l'appariement dépend d'un ordre non garanti sous parallélisme. Appels séquentiels avec `time.sleep(1/ratePerSecond)` : 500 appels à 5/s bloquent un thread de worker plus de 100 s sans checkpoint ; un échec à mi-course ne garde pas trace des outils déjà exécutés. Aucun `DELETE` de `Mcp-Session-Id` en fin de run. Le plafond de 500 appels limite l'impact.
- Reproduction : par lecture ; relancer après échec à l'appel 250 rappelle les 250 premiers outils.
- Correctif : table d'entrée matérialisée avec `rowid` stable, DELETE de session en `finally`, curseur dans le checkpoint de nœud.

## Avantages et différenciateurs

- Porte d'op expérimentales appliquée de bout en bout : écriture (service, routes, MCP, `_validate_node`), exécution (`runtime._prepare`) et catalogue.
- Egress uniforme : chaque appel HTTP des 32 op passe par une session gardée SSRF avec épinglage DNS ; secrets liés à un `baseUrl`.
- TLS vérifié obligatoire sur Mongo/AMQP/FTPS (aucune option de désactivation), même si elle limite la PKI privée (#9).
- Infrastructure de reprise (`reader_state.py`, checkpoints de nœud) déjà présente : #8 se corrige en la branchant.
- Parité de couverture de connecteurs face à FME comme positionnement produit ; #6 (géométrie native des lecteurs SQL) serait le différenciateur décisif.
