# Audit d02 — 3D, terrain, temps, animation (2026-10-16)

Lecture seule ; aucune suite de tests lancée. Les chiffres de coût du proxy sont déduits de la lecture du code, non mesurés.

**Socle sain** : proxy tileset authentifié avec plafonds, garde de privilège sur toutes les routes d'upload, conversion COG isolée dans un process fils, filtre temporel de tuiles par `setFilter` sans recréer les couches.

Synthèse : 8 constats vérifiés (8 Important), 3 Minor non vérifiés.

## Constats vérifiés — Important

### 1. [bug] Tilesets 3D hébergés illisibles pour un invité (lien de partage / embed)
- Fichiers : `shell/src/map/mapDeckTerrain.ts:45-60`, `shell/src/map/MapView.tsx:333-345`, `core/app/tileset3d/routes.py:243-254`
- Preuve : `buildTiles3DLayer` ne pose que `Authorization: Bearer` via `getAuthToken` (l.46-50) ; le jeton de partage n'y est pas passé (`applyDeckLayers` ne reçoit que `getAuthToken`/`getCoreUrl`). MapLibre le gère dans `transformRequest` (MapView.tsx:333-345). La route proxy accepte l'invité (`get_share_link_actor` + `can_read_item`, en-tête `X-Share-Link-Token`). Un tileset partagé ou embarqué renvoie 404 sur `tileset.json`, couche vide.
- Reproduction : lien de partage sur une carte avec couche tiles3d hébergée, ouvrir en navigation anonyme ou via `/embed/:token` : `GET /v1/tileset3d/{id}/tileset.json` part sans `X-Share-Link-Token` → 404.
- Correctif : passer `getShareLinkToken` à `applyDeckLayers`/`buildTiles3DLayer`, poser `X-Share-Link-Token` dans `loadOptions.fetch.headers` sans jeton utilisateur ; test E2E de carte partagée avec tiles3d.

### 2. [bug] Jeton OIDC figé à la construction de `Tile3DLayer`
- Fichiers : `shell/src/map/mapDeckTerrain.ts:46-52`, `shell/src/map/MapView.tsx:397`, `:529`
- Preuve : `token` lu une fois à la construction, figé en valeur littérale dans `loadOptions.fetch.headers`. La couche n'est reconstruite que sur changement de config, pas au rafraîchissement du jeton ; les tuiles b3dm/glb chargées ensuite partent avec un jeton périmé.
- Reproduction : tileset 3D hébergé, naviguer au-delà de la durée de vie du jeton sans toucher la config, zoomer sur de nouvelles zones → 401.
- Correctif : `loadOptions.fetch` en fonction `(url, opts) => fetch(url, {...opts, headers:{...opts.headers, Authorization:`Bearer ${getAuthToken()}`}})` relisant le jeton à chaque requête, ou relancer `applyDeckLayers` à chaque refresh.

### 3. [bug] Proxy tileset3d : zip rouvert, répertoire central reparsé, config rechargée à chaque tuile
- Fichiers : `core/app/tileset3d/routes.py:240-285`, `core/app/tileset3d/storage.py:25-60`, `core/app/configs/repository.py:101-108`
- Preuve : `read_tileset3d_entry` (route synchrone) enchaîne pour chaque tuile `can_read_item`, `get_config_by_item` (dernière révision + validation Pydantic), `head_object` S3 (`S3RangeFile`), puis `zipfile.ZipFile(range_file)` qui relit l'EOCD et le répertoire central en GET Range. Plafond 20000 entrées (`CORE_TILESET3D_MAX_ENTRIES`) : jusqu'à 20000 `ZipInfo` parsés par tuile, avec des dizaines de requêtes simultanées. Aucun cache par (sourceKey, ETag).
- Reproduction : tileset de ~20000 entrées ; par tuile 1 `head_object` + ≥2 `get_object` Range + parsing en threadpool (déduit, non mesuré).
- Correctif : LRU borné (clé sourceKey+ETag) de `name -> (header_offset, size, compress_type)` et du payload `tileset3d` minimal par item_id ; servir par un seul Range S3 ; relayer le Range client pour les entrées STORED ; idéalement pré-indexer à la finalisation.

### 4. [securite] Validation du zip 3D Tiles insuffisante
- Fichiers : `core/app/tileset3d/storage.py:96-111`, `core/app/tileset3d/jobs.py:60-68`, `:121-126`
- Preuve : `zf.read('tileset.json')` puis `json.loads`, seul garde-fou `max_entry_bytes` (2 Gio par défaut, jobs.py:65) : jusqu'à 2 Gio en RAM du worker, sans limite de profondeur JSON. `tilesetJsonPath` codé en dur `'tileset.json'` (jobs.py:123) et racine exigée (storage.py:96) : un zip avec dossier racine (Cesium ion, 3D Tiles Next, Blender/Pix4D) est rejeté. Seule `asset.version` est vérifiée ; ni `root.boundingVolume`, ni `geometricError`, ni les `content.uri` externes ; aucune emprise persistée.
- Reproduction : (1) `tileset.json` de 1,5 Gio lu entièrement ; (2) zip `monDossier/tileset.json` refusé (« aucun tileset.json à la racine »).
- Correctif : plafonner la lecture (≈64 Mio, `zf.open().read(limit+1)`) ; détecter le `tileset.json` le moins profond et le stocker dans `tilesetJsonPath` ; valider `asset.version` ∈ {1.0, 1.1} et `root.boundingVolume` ; persister bbox/centre dans `Tileset3DPayload`.

### 5. [parite] Aucune interaction avec la 3D
- Fichiers : `shell/src/map/mapDeckTerrain.ts:45-60`, `shell/src/map/useMapPopup.ts:63`, `core/app/configs/schemas.py:132-158`
- Preuve : `Tile3DLayer` reçoit seulement id/data/loader/loadOptions/onTilesetLoad : ni `pickable`/`onClick`, ni couleur, ni opacité (alors que `MapLayer.opacity` existe), ni `3d-tiles-style`. `useMapPopup` ignore tiles3d (commentaire l.63). `MapLayer` sans champ 3D (style, décalage vertical, erreur géométrique max, emprise). Pas de `flyTo` après chargement.
- Reproduction : tileset de bâtiments, clic sur un bâtiment : aucun popup ; pas de coloration par attribut, d'opacité ni de zoom sur l'emprise.
- Correctif : `Tiles3DStyle` (couleur data-driven par champ de batch table, réutilisant la symbologie SP-25/27), `opacity`, `pickable` + popup via `info.object.content.batchTable`, `onTilesetLoad -> fitBounds` sur `boundingVolume`, `heightOffset`.

### 6. [bug] `timePlayer` : contexte analytique désynchronisé en fin de plage
- Fichiers : `shell/src/builder/widgets/timePlayer.tsx:106-129`, `:138-139`
- Preuve : l'effet de poussée (l.118-126) n'agit que si `playing`. En fin de plage `windowAt` renvoie null → `setPlaying(false); setIndex(0)` sans `setTimeRange(null)` ni fenêtre 0. L'UI (`shown`, index 0) montre la première période, les widgets liés restent filtrés sur la dernière. Ni nettoyage au démontage/pause, ni bouton « Tout afficher ».
- Reproduction : timePlayer + tableau lié au temps, lecture jusqu'à la fin : affichage « du 01/01 au 07/01 », tableau filtré sur la dernière semaine, jusqu'au prochain play.
- Correctif : en fin de plage `setTimeRange(null)` (ou fenêtre 0, cohérent avec l'affichage), bouton « Réinitialiser », `setTimeRange(null)` au démontage.

### 7. [differenciateur] Temps limité aux jours et aux couches vector/feature
- Fichiers : `shell/src/map/MapTimePlayer.tsx:16-120`, `shell/src/builder/widgets/timePlayer.tsx:23-47`, `shell/src/map/mapApplyLayers.ts:545-583`, `core/app/configs/schemas.py:167-176`
- Preuve : pas/fenêtres en jours entiers (`stepDays`/`windowDays` 1..3660), dates AAAA-MM-JJ, bornes UTC. Seules `vector` (`setFilter`, mapApplyLayers.ts:551) et `feature` (`datetime=`) ont un `timeField`. Pas de slider (lecture/pause + vitesse), ni cumul, ni boucle, ni pas infra-journalier, ni raster/COG/WMS-T, ni 3D, ni export GIF/MP4 (alors que le worker Playwright existe), ni détection de l'étendue min/max : bornes saisies à la main.
- Reproduction : événements horodatés à l'heure, animation par heure impossible ; raster temporel sans contrôle ; aucun scrub sur une date.
- Correctif : modèle en ms + unité, slider avec scrub, mode cumulatif, boucle ; étendue via `/aggregate` sur `timeField` ; `timeField` pour rasters (paramètre `time` TiTiler/WMS-T) ; export via le worker d'export (frames Playwright → MP4/GIF). Différenciateur face au Time Slider ArcGIS.

### 8. [bug] DEM terrain validé seulement sur le CRS
- Fichiers : `core/app/terrain3d/conversion.py:111-130`, `core/app/terrain3d/routes.py:106-118`
- Preuve : `convert_to_cog` vérifie `src.crs is not None` puis `cog_translate` deflate. Rien sur `count==1`, dtype, nodata (-9999/-32768 encodés en relief extrême), plage d'altitudes. La tuile appelle TiTiler avec `algorithm=terrarium` : un ortho RGB uint8 ou un DEM à nodata non déclaré donne un relief aberrant, job « succès ».
- Reproduction : orthophoto GeoTIFF RGB ou SRTM avec -32768 non déclaré : item créé, terrain déformé (pics à 32 km).
- Correctif : exiger `count==1` et dtype adapté, lire min/max, refuser ou masquer le nodata ; stocker min/max/emprise dans `Terrain3DPayload`.

### 10. [dette] Proxy de tuiles terrain : TiTiler synchrone, sans cache serveur (non vérifié)

## Avantages et différenciateurs

- Proxy tileset authentifié sous `can()`, zip jamais extrait, plafonds d'entrées et de taille : posture sécurité supérieure à un simple hébergement statique de 3D Tiles.
- Conversion DEM→COG isolée dans un process fils ; terrain servi par le cœur sous droits.
- Filtre temporel de tuiles par `setFilter` sans recréation de couche : animation fluide sur vector.
- Lecteur temps disponible en widget d'App (contexte temps partagé avec les widgets liés) et en carte ; export Playwright déjà présent, base d'un export vidéo qu'ArcGIS Time Slider n'offre pas nativement (constat 7).
- Opportunité : couplage 3D + temps + symbologie SP-25/27 sous un même document déclaratif, opérable par MCP/IA.
