# Audit d07 — Collecte terrain, XLSForm, mobile, offline

Date : 2026-10-16. Lecture du code uniquement, aucun test exécuté. Les numéros de ligne de `form.tsx` sont approximatifs (±5) ; ceux de `parser.py` ont été revérifiés (266, 295-317, 73-74).

Synthèse : 10 constats (1 Critical, 6 Important, 2 Minor non vérifiés, plus le constat 8 Important). Constats écartés par vérification : 0.

## Critical

### C1 — Aucune capacité offline (Q11) — tag : differenciateur
- **Preuve** : aucun fichier de `shell/` ne contient serviceWorker/IndexedDB hors i18n et `ConnectivityBanner` ; `shell/public` ne contient que `fixtures/` ; ni `shell/index.html` ni `vite.config.ts` ne déclarent de manifest PWA (le seul `manifest: true`, `vite.config.ts:15`, sert au filet de taille de bundle). `form.tsx` (~755-775) appelle directement `client.createFeature` : en cas d'échec réseau, la saisie reste dans l'état React. `ConnectivityBanner.tsx` n'affiche qu'une bannière. ArcGIS Field Maps/Survey123, Kobo et ODK collectent hors ligne.
- **Reproduction** : ouvrir une App de collecte mobile, couper le réseau, remplir et enregistrer : erreur générique, rien en file. Recharger : saisie perdue. Aucun écran « à synchroniser ».
- **Correctif** : PWA installable (manifest + service worker) ; file IndexedDB des saisies (feature + photos) avec ID client idempotent et rejeu à la reconnexion (Background Sync si dispo) ; cache du schéma, des domaines et de la config d'App ; état de synchro dans « Mes saisies » (en attente, envoyée, en conflit) ; puis fonds de carte hors ligne. Côté cœur : accepter un identifiant de saisie fourni par le client.

## Important

### I1 — Photo perdue en silence si l'envoi échoue après la création — tag : bug
- **Preuve** : `form.tsx` ~766-776 : l'échec de `uploadAttachment` appelle `setGenericError(true)` (l.774). Puis `handleSubmit` appelle `resetTo()` (l.923, `editingId===null`), et `resetTo()` (l.835-850) exécute `setGenericError(false)` (l.842) et vide `pendingFiles`. Erreur effacée au même rendu, fichier supprimé.
- **Reproduction** : mode mobile avec champ photo ; faire échouer le PUT S3 juste après `createFeature`. Saisie créée, formulaire vidé, aucun message, photo perdue.
- **Correctif** : ne pas appeler `resetTo()` tant que des fichiers sont en échec ; conserver les fichiers, afficher l'erreur, proposer « Réessayer l'envoi de la photo » sur la saisie créée (mode édition avec son fid). À terme, brancher sur la file offline de C1.

### I2 — Envoi S3 présigné : Content-Type divergent, réponse du PUT non vérifiée — tag : bug
- **Preuve** : présignage et confirmation utilisent `contentType = file.type || "application/octet-stream"`, mais le PUT (`form.tsx:306`) envoie `headers: {"Content-Type": file.type}` (vide pour .gpx, certains .heic). Le cœur signe `ContentType` (`ingestion/storage.py:118-121`). `fetch` n'est pas testé via `.ok` : l'échec n'apparaît qu'au confirm (`head_object` → 404 « objet introuvable »), sans lien avec la cause. Déduit du code ; le comportement exact d'un en-tête vide dépend du navigateur.
- **Reproduction** : joindre un fichier à `file.type` vide sur une saisie existante : PUT avec Content-Type vide pour une URL signée `application/octet-stream`, risque de 403 puis message trompeur.
- **Correctif** : envoyer la variable `contentType` déjà calculée ; tester `res.ok` et lever une erreur explicite avec le statut.

### I3 — Import XLSForm : libellés de choix perdus — tag : parite
- **Preuve** : `parser.py:266` `choices.setdefault(c["list_name"], []).append(c["name"])` ne garde que `name` ; `label` / `label::langue` jamais lus. `form.tsx:63` construit `label: String(v)`. Aucune entrée de rapport.
- **Reproduction** : feuille choices `name=bon, label=Bon état` : l'App affiche « bon ».
- **Correctif** : étendre `FieldDomain` avec `labels: {valeur: libellé}` (multilingue `label::fr`), propager à `applyDomains`, popup et tables ; à défaut, entrée de rapport « approximated ».

### I4 — XLSForm : répétitions, calculate, choice_filter, default, select_multiple — tag : parite
- **Preuve** : `parser.py:293-303` begin_repeat et ses questions `not_ported` ; `:317` calculate non porté ; `:88-95` default, appearance, choice_filter, read_only, repeat_count, parameters signalés non portés ; ~340 select_multiple en texte libre ; fonctions XPath hors du petit sous-ensemble de `to_cel` refusées (`:396`, `:410`). Le rapport est honnête mais un formulaire réel est très dégradé. Les relations ARC-21 permettent de modéliser une répétition en collection fille.
- **Reproduction** : importer un XLSForm Kobo/Survey123 classique (repeat de ménages, cascade choice_filter, calculate de score) : tout figure en non porté.
- **Correctif** (par valeur) : (a) choice_filter → domaines conditionnels CEL ; (b) repeat → collection fille ARC-21 + sous-formulaire ; (c) calculate → colonne calculée CEL ; (d) default → valeur par défaut de colonne ; (e) select_multiple → colonne `text[]` + widget multi-choix ; (f) étendre `to_cel` (today, string-length, regex, coalesce).

### I5 — Géométrie : points en lon/lat seulement ; lignes/polygones non saisissables — tag : parite
- **Preuve** : `form.tsx` ~912-916 : `geometry = geometryType === "Point" ? {Point depuis lon/lat} : loadedGeometry`, `loadedGeometry` nul à la création ; contrôles rendus seulement pour Point (~1063/1076). Pourtant `parser.py:73` mappe geotrace→LineString, geoshape→Polygon. Pas de sélection sur carte, précision GNSS (`coords.accuracy`), altitude et heure du fix non lues (`locate()`, ~686-696). Géométrie requise non imposable.
- **Reproduction** : importer un XLSForm avec geotrace : aucun moyen de tracer, enregistrement créé avec `geometry=null`.
- **Correctif** : intégrer l'outil de croquis SP-27/SP-51 : point au tap, ligne, polygone, trace GPS (`watchPosition`) ; colonnes optionnelles accuracy/altitude/horodatage ; refus serveur si géométrie requise absente.

### I6 — Champs audio/vidéo/fichier : saisie images seulement, API publique refuse audio/vidéo — tag : parite
- **Preuve** : `parser.py:74` `_FILES = {image, photo, audio, video, file}` → tous `attachment` ; `form.tsx` (~412-418, `capture` l.415) rend `accept="image/*" capture="environment"` pour tout attachment. `public_submit/service.py:_SNIFF` n'accepte que JPEG/PNG/GIF/WEBP/PDF, 415 sinon (`routes.py` ~144). Le type n'est pas porté par le champ (`{key,label}`) ; l'import n'avertit pas.
- **Reproduction** : importer `audio note_vocale` : le champ ouvre l'appareil photo.
- **Correctif** : porter le type dans `attachment_fields`, l'utiliser pour `accept`/`capture` ; ajouter magic numbers audio/vidéo à la liste blanche ; annotation d'images et compression côté client.

### I7 — Aucun écran citoyen pour la soumission publique — tag : differenciateur
- **Preuve** : `core/app/public_submit/routes.py:60` expose `POST /public/submit/{token}` (multipart, 1 photo, honeypot, modération). Côté `shell/src`, seuls `SubmissionsPanel.tsx` (modération) et `api/domains/features.ts` s'y rapportent ; aucune page/route de formulaire public. Jeton à usage global (quota total, pas d'identité), un fichier par soumission.
- **Reproduction** : créer un jeton, chercher une URL du shell qui l'accepte : aucune.
- **Correctif** : route publique `/collect/:token` (même patron que `/embed/:token`) rendant le formulaire de la collection, avec captcha/preuve de travail, plusieurs fichiers, mode hors ligne ; QR depuis la fiche du jeton.

## Minor (non vérifiés)

### M1 — Pièces jointes : fid non vérifié, s3_key confirmable en doublon, lecture en mémoire — tag : securite — NON VÉRIFIÉ
- **Preuve** : `attachments/routes.py` (confirm_attachment ~175-225) ne contrôle que le droit d'écriture ; pas d'unicité sur `s3_key` (`models.py:20-33`) ; suppression d'une ligne efface l'objet S3 (`repository.py:108`) et casse les autres ; `read_attachment_file` (~326) lit jusqu'à 25 Mo en RAM ; `content_type` pris du corps, non de `head_object`.
- **Reproduction** : confirmer deux fois la même clé puis supprimer une ligne ; POST avec fid inexistant : 201.
- **Correctif** : index unique `(tenant_id, s3_key)`, vérifier le fid sous `rls_scope`, `content_type` de `head_object`, streaming ou GET présigné, magic numbers.

### M2 — `required` non appliqué côté serveur ; XLSForm non réimportable/exportable — tag : parite — NON VÉRIFIÉ
- **Preuve** : `required` seulement dans `form_fields` (validation client, `form.tsx` ~317-325) ; colonnes sans NOT NULL ni règle ; `xlsform/routes.py:56-72` appelle toujours `create_empty_collection` (doublon à la réimportation) ; pas d'export XLSForm.
- **Reproduction** : XLSForm avec `required=yes`, puis POST d'une feature sans la propriété : accepté ; réimporter : deuxième collection.
- **Correctif** : attribute_rule CEL « not null » par question requise ; `POST /xlsform/import?collectionId=…` (mise à jour + rapport de différences) ; export XLSForm.

## Avantages et différenciateurs
- Import XLSForm avec rapport honnête (`not_ported` / `approximated`) plutôt qu'une perte silencieuse ; `relevant` et `constraint` traduits en CEL.
- Chaîne complète déjà présente : collection + App générées, « Mes saisies », modération des soumissions publiques (honeypot, quota), pièces jointes S3 présignées sous `can()`, relations entre collections (ARC-21) et moteur CEL réutilisables pour combler les écarts de C1/I4.
- Une fois l'offline (C1) et la page publique (I7) livrés, la plateforme couvre le parcours Survey123/Kobo sur une même pile open-source.
