# d30 — RGPD, souveraineté, conformité

Audit du 2026-10-16. Lecture du code uniquement, rien n'a été exécuté.
Constats Important : relus dans le code (verified). Constats Minor : non vérifiés (marqués comme tels).

Synthèse : les mécanismes d'effacement (`anonymize_user`, `purge_tenant`, reçu de purge) sont bien construits. Les trous sont ailleurs : pas de droit d'accès ni de portabilité, journal d'audit sans rétention ni intégrité, effacement non rejoué après restauration, purge « done » malgré un nettoyage S3 raté, liens de partage d'un compte effacé toujours valides, fonds de carte tiers codés en dur.

## Important

### 1. Aucun droit d'accès / portabilité (RGPD Art. 15/20) — tag `parite`
- Preuve : `core/app/compliance/routes.py` ne déclare que 3 routes : `POST /compliance/users/{id}/erase` (l.37), `POST /tenants/{id}/purge` (l.95), `GET /purges/{id}` (l.162). `core/app/auth/routes.py` n'expose que `GET /me`, `/users/directory`, `/users`. Aucun outil MCP équivalent.
- Reproduction : chercher une route d'export des données d'un sujet : aucune. Un DPO ne répond à une demande d'accès qu'en SQL manuel.
- Correctif : `GET /v1/compliance/users/{id}/export` (privilège `compliance.manage`, ou self pour « me »). JSON/zip : profil, items possédés, partages, lignes `audit_log` où `actor_id` = user, `entity_history`. Auditer l'export. À publier comme différenciateur (« dossier RGPD en un clic »).

### 2. `audit_log` : ni rétention, ni immuabilité, ni intégrité — tag `securite`
- Preuve : `core/app/audit/models.py` : table ordinaire, sans hash chaîné ni signature. Aucun trigger ni `REVOKE UPDATE/DELETE` dans `alembic/versions`. Aucune tâche de rétention : seule suppression = `purge_tenant` (`core/app/compliance/purge.py:331-332`), alors que `history/service.py:25` a 365 j. Écritures via `app/audit/writer.py:6-29`. Aucune route d'export ni de vérification.
- Reproduction : avec le rôle SQL de l'application, `UPDATE audit_log SET actor_id=NULL ...` ou `DELETE` passe sans trace.
- Correctif : (1) trigger `BEFORE UPDATE OR DELETE` levant une exception sauf rôle de purge ; (2) colonnes `prev_hash`/`hash` chaînées (sha256) ; (3) cron de rétention `CORE_AUDIT_RETENTION_DAYS` avec export S3 signé avant suppression ; (4) route d'export pour le DPO.

### 3. Effacements non rejoués après restauration d'une sauvegarde — tag `securite`
- Preuve : `deploy/backup/retention.py:25-26` garde 7 quotidiennes + 4 hebdomadaires. `restore.sh` restaure la base telle quelle. `users.erased_at`, le tombstone `oidc_sub` et `PurgeReceipt` vivent dans cette même base : un utilisateur anonymisé retrouve nom et e-mail, un tenant purgé réapparaît. Aucun registre hors base ni rejeu dans `deploy/backup/*.sh`.
- Reproduction : anonymiser un utilisateur, restaurer l'archive de la veille : `users` porte à nouveau username/email, rien ne ré-anonymise.
- Correctif : journal d'effacement append-only hors base (objet S3, `erasures.jsonl` : id + horodatage, jamais de PII), conservé plus longtemps que les sauvegardes ; étape de `restore.sh` qui le rejoue (`anonymize_user`/`purge_tenant`) ; documenter la fenêtre de 35 jours dans `SECURITY.md`.

### 4. `purge_tenant` : reçu « done » malgré un nettoyage S3 raté ; lac CDC non balayé — tag `bug`
- Preuve : `purge.py:348` pose `receipt.status = "done"` avant le callback post-commit. Le callback (l.153-170) avale l'exception et ne fait que `counts.s3_cleanup_failed=1` (l.168), sans retry ni changement de statut. La ligne `tenants` est supprimée (l.352) : plus rien ne retrouve le préfixe. `core/app/compliance/orphans.py:205-227` ne couvre ni le bucket du lac (`geostudio-cdc`) ni `{tenant}/pipelines/` (exclu l.30-31). Des GeoParquet de données personnelles peuvent rester indéfiniment sous un reçu « done ».
- Reproduction : rendre S3 indisponible pendant le callback (ou faire échouer `lake_purge.purge_prefix`) : reçu `done` avec `s3_cleanup_failed=1`, tenant supprimé, objets présents.
- Correctif : statut `done_with_s3_pending` si échec ; cron qui retente la purge des préfixes `{tenant}/` et du lac pour tout reçu portant `s3_cleanup_failed` (conserver le `tenant_id` dans le reçu) ; étendre `sweep_orphan_job_objects` au bucket cdc.

### 5. Effacement d'un compte : ses liens de partage restent valides — tag `securite`
- Preuve : `core/app/compliance/service.py:52-99` (`anonymize_user`) révoque clés d'API, notifications, membres de groupe, historique d'acteur, mais pas les `ShareLink`. La résolution (`core/app/items/routes.py:342-372`) ne vérifie que `link_creator_can_still_share` (`items/service.py:45-51`) = `can(created_by, "share")`. `sharing/authorization.py:115-116` renvoie `True` dès que `item.owner_id == user_id`, sans test de `erased_at`. Le compte anonymisé reste propriétaire de ses items : ses liens publics et jetons invités restent actifs jusqu'à expiration.
- Reproduction : A crée un share link, puis `POST /compliance/users/me/erase` ; `GET /v1/share-links/{token}` renvoie encore 200.
- Correctif : dans `anonymize_user`, `UPDATE share_links SET revoked_at=now() WHERE created_by=user_id` ; révoquer aussi `SubmissionToken`, `PipelineWebhookToken`, `ReportSchedule`/`AlertRule` créés par lui ; défense en profondeur : `link_creator_can_still_share` refuse si `User.erased_at` non nul.

### 6. Souveraineté : fonds de carte tiers codés en dur — tag `differenciateur`
- Preuve : `shell/src/map/basemaps.ts:6-18` : trois fonds, tous externes (`demotiles.maplibre.org`, `basemaps.cartocdn.com`) ; `DEFAULT_BASEMAP = BASEMAPS[0]` (l.20) ; `shell/src/builder/widgets/mapWidget.tsx:34` utilise demotiles ; `core/app/ingestion/importer.py:59` écrit ce style dans chaque carte importée ; `core/app/configs/builder_templates.json:758-759` référence cartocdn. La liste par tenant (`/v1/basemaps`) s'ajoute mais `useBasemaps.ts:25-26` conserve toujours les trois externes. Chaque affichage envoie IP et user-agent à des CDN tiers : incompatible SecNumCloud/HDS/RGS et CSP strict (SP-48).
- Reproduction : réseau fermé, toute carte reste blanche ; réseau ouvert, l'inspecteur montre les requêtes vers ces hôtes.
- Correctif : variable opérateur (`CORE_DEFAULT_BASEMAP_STYLE` ou `VITE_*`) exposée via `/instance` ; mode `sovereign` masquant les fonds externes ; fond par défaut auto-hébergé (Martin + PMTiles/Protomaps) et style IGN Géoplateforme ; remplacer les constantes de `importer.py` et des gabarits.
