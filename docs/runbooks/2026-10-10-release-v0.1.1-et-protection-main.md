## (b) Release v0.1.1

Pipeline (`.github/workflows/release.yml`, déclenché par un tag `v*.*.*`) :
`verify-tag` (tag == `GEOSTUDIO_VERSION` de `.env.example` ; commit atteignable
depuis `origin/main` ; `ci.yml` vert sur ce SHA) → `test-gate` + `test-gate-arm64`
→ `build-and-push` (`_build-and-push.yml`, 9 images, `:latest` en plus) →
`verify-published` (`check_published_images.py <tag>`, authentifié).

Images de la matrice : core, shell, postgis, titiler, appexport-standalone,
export-worker, appexport-runtime-builder, backup, minio. **v0.1.0 n'a pas
titiler ni minio** : v0.1.1 les publie (minio : build AGPL depuis sources,
`deploy/minio/Dockerfile`, long ; export-worker 3 Go).

Procédure :
1. Promouvoir `dev` → `main` par PR (`git push origin dev` puis
   `gh pr create --base main --head dev`), attendre `ci.yml` vert.
2. Sur une branche/PR : bumper `GEOSTUDIO_VERSION=v0.1.1` dans `.env.example`
   **et** `geostudio_version` dans `deploy/proxmox/ansible/group_vars/all.yml` et
   `deploy/oci/ansible/group_vars/all.yml` (gardé par `test_deployability`),
   dater `CHANGELOG.md` (`[Unreleased]` → `[0.1.1] - <date>`), merger dans `main`.
3. Attendre `ci.yml` vert **sur le SHA exact de `main`** à tagger.
4. `git checkout main && git pull && git tag v0.1.1 && git push origin v0.1.1`.
5. Suivre `gh run watch` ; en cas d'échec d'une leg, `fail-fast: false` laisse
   les autres publier : relancer le job échoué seulement.
6. Vérifier : `cd core && GITHUB_TOKEN=$(gh auth token) python3
   scripts/check_published_images.py v0.1.1` → 9/9 ; contrôler que les paquets
   GHCR nouveaux (titiler, minio) sont en visibilité **publique** (GHCR crée en
   privé par défaut).
7. Créer la GitHub Release : `gh release create v0.1.1 --notes-from-tag` (ou
   depuis CHANGELOG).

Rupture à annoncer dans la release : retrait de `transform.qgis` ; MinIO
reconstruit (changement de version serveur, cf. CHANGELOG) ; le cœur refuse de
démarrer si `S3_PUBLIC_ENDPOINT_URL` est vide hors `CORE_ENV=development`
(REV-315) ; `start_period` du cœur 180 s (REV-320).

## (c) Migration Keycloak : politique Trusted Hosts (DCR) sur instance existante

Constat : `kc.sh start --import-realm` n'importe le realm **que s'il est
absent**. `scripts/install.sh` ne resynchronise que `redirectUris`/`webOrigins`/
`post.logout.redirect.uris` du client shell, **pas** la politique Trusted Hosts
(la note « install.sh resyncs the policy » du CHANGELOG était inexacte, corrigée
ce jour). Une instance créée avant l'ajout de la politique garde donc
l'enregistrement dynamique de clients plus ouvert que prévu.

Cible (cf. `deploy/keycloak/geostudio-realm.json`, `deploy/keycloak/README.md`) :
politique anonyme `trusted-hosts`, `client-uris-must-match=true`,
`host-sending-registration-request-must-match=false`, hôtes `localhost`,
`127.0.0.1`, `claude.ai`.

Procédure console (la plus sûre) : *Realm geostudio → Realm settings → Client
registration → Client registration policies → Anonymous access policies*,
créer/éditer **Trusted Hosts** avec les valeurs ci-dessus.

Procédure `kcadm` (non rejouée ici : aucune stack touchée — **à valider sur une
instance de test avant la prod**) :

```bash
C="docker compose -f docker-compose.yml -f docker-compose.prod.yml"
kc=/opt/keycloak/bin/kcadm.sh
grep '^KC_PASSWORD=' .env | cut -d= -f2- | $C exec -T keycloak $kc config credentials \
  --server http://localhost:8080/auth --realm master --user admin --client admin-cli
$C exec -T keycloak $kc get components -r geostudio \
  -q providerId=trusted-hosts          # lire l'état actuel (id éventuel)
# si présent : update components/<id> ; sinon : create components
$C exec -T keycloak $kc update components/<id> -r geostudio \
  -s 'config."trusted-hosts"=["localhost","127.0.0.1","claude.ai"]' \
  -s 'config."client-uris-must-match"=["true"]' \
  -s 'config."host-sending-registration-request-must-match"=["false"]'
```

Vérification : `POST /auth/realms/geostudio/clients-registrations/openid-connect`
avec un `redirect_uris` sur un hôte tiers → **403** ; sur `claude.ai` → 201.
