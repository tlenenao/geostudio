## 0. Règles de ce plan

1. **Phase 0 d'abord (piège n°12)** : chaque entrée est re-vérifiée dans le code avant toute tâche. Une entrée déjà fermée par le code est fermée par commit de preuve, sans nouvelle implémentation (précédent : REV-033, REV-188).
2. **« Clore » a trois sens ici**, à ne pas confondre dans le backlog : *fermé par code*, *fermé par décision* (précédents REV-063/123/166 : ADR ou note datée), *fermé par action humaine* (réglage GitHub, release). Aucune entrée n'est déclarée fermée sans preuve du sens retenu.
3. Les 7 gaps produit (112/114/115/117/119/120/121) sont des chantiers de 5 à 30 j chacun : **ils ne sont pas dans le chemin critique**. Ils ont un gate de décision (lot 6) ; seuls ceux validés par Tanguy passent par brainstorm → spec → plan propres.
4. Jumelles (piège n°14) : pour chaque correctif, lister les sites jumeaux avant de clore (ex. 310 ↔ runs cron/webhook ; 313 ↔ `__in` MVT/OGC/STAC ; 301 ↔ tout `psycopg.connect` direct ; 315 ↔ tous les clients S3 présignés).
5. Clôture transverse à chaque lot : régénérer OpenAPI + types TS si route/modèle change ; `inventaire-fonctionnalites.jsonl` + `feature_health_cli.py --write` si surface nouvelle ; recompter le backlog avec `scripts/revue/count-backlog-etat.sh`.
