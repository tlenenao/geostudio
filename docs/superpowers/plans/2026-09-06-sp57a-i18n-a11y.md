# SP-57a — i18n complète + audit d'accessibilité : implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fermer les volets 5.1 (i18n) et 5.2 (accessibilité) de GAP-14
(vague 5, qualité transverse) : migrer les 110 fichiers `.tsx` restants
(`pages/`, `shell/`, `builder/`, `map/`) vers `t()` sans changer le texte
affiché, et outiller un audit d'accessibilité automatisé (axe-core) sur un
échantillon représentatif de 9 pages.

**Architecture:** 12 tâches — Task 1 pose le détecteur de couverture i18n
(filet avant tout code) ; Tasks 2-8 migrent les lots de fichiers (ordre :
`pages/` → `shell/` → `builder/widgets/` → `builder/pipeline+misc` →
`builder/` racine (2 lots) → `map/`) ; Task 9 clôt le volet i18n (garde
permanente) ; Tasks 10-11 câblent et étendent l'audit a11y ; Task 12 clôture
le plan.

**Tech Stack:** TypeScript/React + Vitest (détecteur, tests unitaires),
Playwright + `@axe-core/playwright` (audit E2E), Node (script de
couverture).

**Document source :**
`docs/superpowers/specs/2026-09-06-sp57a-i18n-a11y-design.md` (§2 i18n, §3
a11y, §6 décomposition).

## Global Constraints

- **TDD / filet-avant-code** systématique — Task 1 avant toute migration,
  chaque page a11y testée avant sa correction.
- **Le texte affiché ne change jamais pendant la migration i18n** — une
  migration qui modifierait la formulation d'un message est un bug, pas une
  amélioration bienvenue (hors périmètre de ce plan). Les tests Vitest
  existants des composants touchés doivent rester verts **sans modification
  de leurs assertions de texte**.
- **Convention de clé i18n `<domaine>.<intention>` déjà en vigueur** (testée
  par `shell/src/i18n/index.test.ts`) — ne pas en inventer une autre. Avant
  de nommer un domaine pour un nouveau fichier, vérifier si un fichier
  cousin déjà migré a déjà posé ce domaine (ex. `roles.*` par
  `RolesAdminPage.tsx`) et le réutiliser.
- **Suite complète rejouée à la fin de chaque tâche de migration** :
  `cd shell && npm run test` (Vitest) au minimum ; `npm run lint` dès que le
  script de couverture est câblé (Task 9) ; `npm run e2e` en fin de Tasks 9,
  11 et à la clôture.
- **Tout filet de test ajouté est vérifié par falsification** (piège
  CLAUDE.md n°10) — Task 1 Step 3, Task 10 Step 5.
- **Piège CLAUDE.md n°3/12** : SP-43 (primitive `aria-expanded`) n'est pas
  exécuté au moment d'écrire ce plan (0/106 étapes cochées, vérifié) — ne
  pas supposer que `shell/src/ui/kit/usePanelTrigger.ts` existe ; vérifier
  son état réel en début de Task 10 si le module `ui/kit/` a changé depuis.
- **Vérifier chaque décompte avant de le coder** : les listes de fichiers
  ci-dessous ont été énumérées par `git ls-files` au 2026-09-06 — une session
  concurrente a pu ajouter/renommer un fichier depuis ; revérifier avec
  `git ls-files 'shell/src/<dir>/*.tsx' | grep -v '\.test\.tsx$'` avant de
  démarrer chaque tâche de migration plutôt que de faire confiance à la
  liste figée ici.
- **Commits conventional, français, un sujet par commit**
  (`feat(shell): ...`, `test(shell): ...`, `chore(shell): ...`).
